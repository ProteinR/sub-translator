# Translator Automation

Этот проект автоматизирует процесс перевода строк с использованием Anthropic API (Claude). Это одно macOS-окно на системном WebKit (без Playwright и Chromium): вкладка «Панель» — настройки, очередь ссылок, промпт и журнал, а рядом — по вкладке Lokalise на каждый поток перевода. За работой каждого потока можно наблюдать, переключая вкладки.

## Установка на новый компьютер

Нужен macOS 13 или новее (Apple Silicon или Intel). Ничего, кроме самого приложения, ставить не надо.

1. Откройте [последний релиз](https://github.com/ProteinR/sub-translator/releases/latest) и скачайте `Loka-Translator-<версия>.zip`.
2. Распакуйте архив и перетащите **Loka Translator.app** в папку **Программы**.
3. Первый запуск: приложение не подписано сертификатом Apple, поэтому macOS его заблокирует. Откройте **Системные настройки → Конфиденциальность и безопасность**, внизу нажмите **«Всё равно открыть»** у Loka Translator. Либо одной командой в Терминале:
   ```bash
   xattr -dr com.apple.quarantine "/Applications/Loka Translator.app"
   ```
4. В приложении: **Настройки → ключ Anthropic** (создаётся в [Claude Console](https://console.anthropic.com/)), затем добавьте ссылку на проект Lokalise и нажмите **Запустить перевод**. Если Lokalise попросит войти — войдите во вкладке потока, вход сохранится.

Настройки, память переводов и логи хранятся в `~/Library/Application Support/Loka Translator/data`. При первом запуске туда переносятся `config.json` и `tm.jsonl` из папки `data` рядом с приложением, если она есть (так было до версии 3.1).

## Обновления

Приложение само проверяет [релизы на GitHub](https://github.com/ProteinR/sub-translator/releases) при запуске и раз в 6 часов. Когда выходит новая версия, на панели появляется синий баннер с описанием изменений и кнопкой **Обновить**: приложение скачает новую версию, заменит себя и перезапустится. Во время перевода кнопка неактивна. Проверить вручную — клик по номеру версии рядом с названием. Текущая версия: **3.5.1**.

## Разработка

Нужны Go, Git и Xcode Command Line Tools (`xcode-select --install`, для сборки окна на WebKit).

*   `src/start.sh` — `git pull`, сборка `Loka Translator.app` в корне проекта и запуск с логами в Терминале. Такая копия обновляется через git, а не кнопкой.
*   `src/build-app.sh [папка]` — только сборка; `UNIVERSAL=1` — для Apple Silicon и Intel, `APP_VERSION=3.0.9` — подменить номер версии (удобно проверять обновление).
*   `LOKA_BROWSER=1` — панель в обычном браузере вместо окна; перевод работает только в окне на macOS.

### Выпуск новой версии

Из ветки `main`, когда всё закоммичено и отправлено:

```bash
scripts/release.sh 3.2.0 "Что нового — этот текст увидят в баннере обновления"
```

Скрипт прогоняет тесты, ставит номер версии в `src/main.go` и README, собирает universal-приложение, коммитит «Release 3.2.0», ставит тег `v3.2.0`, отправляет в GitHub и создаёт релиз с архивом (нужен `gh`, авторизованный в GitHub). Установленные приложения увидят его в течение 6 часов или сразу после перезапуска.

## Как пользоваться Web-интерфейсом

Интерфейс состоит из двух экранов: **главного** (запуск, очередь, журнал) и **Настроек** (кнопка справа вверху). Всё сохраняется автоматически в `data/config.json` в папке данных (атомарная запись, права `0600`).

1. **Первый запуск.** Пока не указан ключ Anthropic, сверху висит предупреждение, а кнопка запуска неактивна. Откройте **Настройки → Перевод**: ключ, модель (по умолчанию Haiku 5.5), запасная модель и лимит расходов на запуск. Ключ можно задать и переменной окружения `ANTHROPIC_API_KEY`.
2. **Очередь проектов.** Вставьте ссылку Lokalise в поле на главном экране — можно сразу несколько, каждую с новой строки. Поддерживаются страницы с несколькими документами; параметр `files_selection` сохраняется, вид автоматически переключается в **Multilingual**. В Lokalise должны быть видны исходный и все нужные целевые языки: базовая языковая строка — исходник, остальные видимые — цели перевода.
3. **Запуск.** Нажмите **Запустить перевод**. У каждого проекта виден статус (*В очереди*, *В работе* с прогрессом по ячейкам, *Ошибка* с причиной, *Готово*). Готовый проект убирается из очереди; с ошибкой — остаётся, повторный запуск пропустит уже заполненные ячейки. **Остановить** прерывает работу после текущего шага.
4. **Перезаписывать заполненные** — по умолчанию выключено, заполняются только пустые ячейки. Исходник не изменяется никогда.
5. **Журнал** внизу: фильтр *Проблемы* показывает только предупреждения и ошибки.
6. **Правила перевода** (Настройки) — общий стиль и требования к языкам; направление и формат ответа подставляются автоматически. Кнопка *Вернуть рекомендованные* восстанавливает текст по умолчанию.
7. **Дополнительно** (Настройки) — число параллельных проектов и паузы при работе с Lokalise. Меняйте, только если страница не успевает загружаться.

Названия проектов берутся из заголовков `.project-document__file-name` и атрибута строки `data-filename`.

### Как экономятся токены и ловится брак
- **Все языки в одном запросе**: исходник строки отправляется один раз сразу на все целевые языки.
- **Память переводов** (`data/tm.jsonl`): готовые переводы переиспользуются при повторных прогонах и для одинаковых строк. Ключ учитывает модель и промпт — поменяли их, и старые переводы не подмешиваются. Удалите файл, чтобы сбросить память.
- **Контекст**: в каждую пачку уходят 3 предыдущие строки с переводами — для единого пола спикера и терминов.
- **Проверка перед вставкой**: плейсхолдеры и теги, число абзацев, адекватная длина, «перевод» без перевода. Повторно запрашиваются только забракованные ячейки.
- **Запасная модель**: если основная перегружена или дважды ответила некорректно, пачка уходит в запасную. Учтите: Sonnet в ~20 раз дороже Haiku.
- **Prompt caching**: системный промпт помечен для кэширования. Кэш срабатывает, только когда промпт длиннее порога модели (у Haiku — несколько тысяч токенов), поэтому при коротком промпте экономии нет.
- **Расход и лимит**: в шапке показываются токены, примерная стоимость и попадания в память. Лимит расходов останавливает прогон при достижении суммы (проекты остаются в очереди).
6. По умолчанию заполняются только пустые переводы. **Перезапись всех переводов** разрешает замену заполненных целевых ячеек; исходник не изменяется.
7. Проект удаляется из очереди только после успешной обработки всех обнаруженных языков. Если отдельная строка не вставилась (после повторной попытки), обработка идёт дальше, а в конце проект помечается ошибкой со списком строк и остаётся в очереди; повторный запуск пропускает уже заполненные ячейки. **Stop** прерывает обработку, включая ожидающий запрос к API.

### Проверка изменений

Из папки `src` выполните `go test ./...`. Работа со страницей Lokalise — в `src/lokalise.js`: селекторы и вставка текста в редактор (CodeMirror) выполняются внутри вкладки. Для отладки запустите с `LOKA_DEBUG=1`: появится `POST /api/debug/eval` (`{"tab":1,"url":"…"}` открывает адрес, `{"tab":1,"js":"return window.__loka.state()"}` выполняет код во вкладке; нужен заголовок `X-Loka-Request: 1`). Правый клик во вкладке → «Проверить элемент» открывает Web Inspector.

### Авторизация (Первый запуск)
*   Если Lokalise просит войти, приложение само переключится на вкладку потока со страницей входа.
*   **Введите логин и пароль** в этой вкладке (капчу или 2FA — тоже там). Программа ждёт до 10 минут и продолжит сама.
*   Вход общий для всех вкладок и сохраняется между запусками (хранилище WebKit приложения `com.proteinr.loka-translator`).

## Возможные проблемы

*   **Порт 8080 занят**: Запустите с другим портом: `LOKA_PORT=8090 "./Loka Translator.app/Contents/MacOS/loka-translator"`. Сервер слушает только `127.0.0.1` и недоступен из локальной сети.
*   **Ошибка сборки `xcrun` / `clang`**: установите Command Line Tools (`xcode-select --install`).
*   **Ошибки перевода**: При 429/5xx/529 запросы повторяются автоматически с паузой (учитывается `retry-after`). Ошибки 400/401/403 не повторяются — проверьте ключ и название модели. Если страница не успевает загружаться, увеличьте задержки в интерфейсе.
*   **`config.json повреждён`**: Если файл настроек испорчен, интерфейс покажет ошибку и не даст его перезаписать. При следующем сохранении испорченный файл переименуется в `config.json.broken-<дата>`.

### Решение проблем с обновлениями
Если кнопка **Обновить** выдала ошибку, скачайте архив из [релизов](https://github.com/ProteinR/sub-translator/releases/latest) и замените приложение вручную — настройки не пропадут.

## Структура проекта

*   `Loka Translator.app`: само приложение при сборке из исходников (`src/build-app.sh`, в git не хранится). Обычная установка — из релизов.
*   `scripts/release.sh`: выпуск версии на GitHub; `scripts/make-icon.sh` — пересборка иконки из `src/icon/AppIcon.svg`.
*   `src/`: Исходный код и скрипт запуска:
    *   `main.go` — точка входа, HTTP-сервер;
    *   `server.go` — API, защита от CSRF/DNS rebinding, поток логов;
    *   `config.go` — настройки, миграция, атомарная запись;
    *   `anthropic.go` — клиент Anthropic API: структурированный ответ, ретраи, запасная модель, разбиение пачек;
    *   `validate.go` — проверка перевода перед вставкой;
    *   `memory.go` — локальная память переводов;
    *   `usage.go` — учёт токенов, стоимость, лимит бюджета;
    *   `lokalise.go` — сбор строк и вставка переводов (логика, повторы, прокрутка);
    *   `lokalise.js` — код внутри вкладки Lokalise: чтение строк, редактор, кнопка Save;
    *   `browser.go`, `webkit_darwin.go`, `webkit_darwin.m` — окно с вкладками на WebKit и мост Go ↔ JS;
    *   `build-app.sh` — сборка `Loka Translator.app`;
    *   `updater.go` — проверка релизов на GitHub и обновление одной кнопкой;
    *   `runner.go` — оркестрация прогона и уведомления в Telegram;
    *   `progress.go` — статусы и прогресс проектов для интерфейса;
    *   `index.html` — веб-интерфейс (без внешних зависимостей, работает офлайн);
    *   `logger.go` — логи с маскировкой секретов.
*   `data/`: настройки, логи и память переводов (`config.json`, `tm.jsonl`, `logs/`). У установленного приложения — в `~/Library/Application Support/Loka Translator/data`, так же и при запуске через `start.sh`; только `go run` пишет в текущую папку.
